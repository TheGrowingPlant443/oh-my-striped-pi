# Environment Variables (Current Runtime Reference)

This reference is derived from current code paths in:

- `packages/coding-agent/src/**`
- `packages/ai/src/**` (provider/auth resolution used by coding-agent)
- `packages/utils/src/**` and `packages/tui/src/**` where those vars directly affect coding-agent runtime

It documents only active behavior.

## Resolution model and precedence

Most runtime lookups use `$env` from `@oh-my-pi/pi-utils` (`packages/utils/src/env.ts`).

`$env` loading order:

1. Existing process environment (`Bun.env`)
2. Project `.env` from the launch working directory for keys whose current value is empty/unset
3. Active agent `.env` (normally `~/.omp/agent/.env`) for keys whose current value is empty/unset
4. Active config-root `.env` (normally `~/.omp/.env`) for keys whose current value is empty/unset
5. Home `.env` (`~/.env`) for keys whose current value is empty/unset

The agent/root locations respect profiles, `PI_CONFIG_DIR`, and—only for the default profile—`PI_CODING_AGENT_DIR`. Whole dotenv files are parsed with Bun's `node:util.parseEnv`, including quoted multiline values, escaped newlines, and inline comments. Names must be shell identifiers (`[A-Za-z_][A-Za-z0-9_]*`); unsafe names/values are discarded. Variable references remain literal in this parser; only Bun's launch-directory dotenv autoload performs variable expansion before this module runs. Child-shell filtering uses the same parser to identify project dotenv values across `.env`, `.env.<NODE_ENV>` (default `development`), `.env.local`, and `.env.<NODE_ENV>.local`. It removes project-dotenv credentials from shell subprocesses while preserving launcher-owned variables; Linux's original exec environment provides the authoritative launch snapshot, with best-effort value matching elsewhere.

Additional rule inside each `.env` file: every `OMP_*` key is mirrored to its `PI_*` alias, and that mirrored value replaces a same-file `PI_*` value. This mirroring applies to parsed dotenv files, not arbitrary variables inherited from the parent process.

Variables declared on a setting definition (see [settings precedence](./settings.md#precedence)) are parsed by the setting's type unless noted otherwise. Boolean ones (`PI_PY`, `PI_JS`, `PI_INTENT_TRACING`, …) follow `parseFlag`: an empty value is ignored, so the setting applies; `1`, `y`, `true`, `yes`, and `on` (all-lowercase or all-uppercase) mean true; any other non-empty value means false.

## 2) Provider-specific runtime configuration

### Outbound proxy routing

Provider HTTP fetches resolve proxies in this order after applying `NO_PROXY` / `no_proxy`:

1. `PI_PROXY_<PROVIDER>` (provider ID uppercased, non-alphanumerics replaced with `_`, for example `PI_PROXY_GITHUB_COPILOT`)
2. `PI_PROXY`
3. `HTTPS_PROXY` / `https_proxy` for HTTPS and WebSocket targets, or `HTTP_PROXY` / `http_proxy` for HTTP
4. `ALL_PROXY` / `all_proxy`

Provider proxy lookups are cached for the process lifetime. Localhost targets bypass the provider fetch wrapper.

Scope differs between the two `PI_PROXY` forms:

- `PI_PROXY` is installed on the process-wide `fetch` at CLI startup, so it also
  covers requests made outside the provider fetch wrapper — OAuth token refresh
  and login, usage probes, model discovery. Without that, a region-blocked token
  endpoint returns `403 Request not allowed` on refresh even though the stream
  itself is proxied.
- `PI_PROXY_<PROVIDER>` applies only to that provider's requests, and overrides
  `PI_PROXY` for them. It does not cover the non-provider-scoped calls above; set
  `PI_PROXY` too if the provider blocks your region.

Loopback, link-local, private-range (`10/8`, `172.16/12`, `192.168/16`), and
`NO_PROXY` targets always bypass, so local model servers and MCP hosts stay direct.

### Request body compression

Request bodies of 1 KiB or more can be compressed for GitHub Copilot endpoints that advertise support (zstd, falling back to gzip). Other hosts receive uncompressed JSON. If an endpoint rejects an encoding and an uncompressed resend succeeds, that encoding stays off for that host for the rest of the process.

| Variable                 | Behavior                                                                          |
| ------------------------ | --------------------------------------------------------------------------------- |
| `PI_REQUEST_COMPRESSION` | `0`/`false`/`no`/`off` sends every request body uncompressed (enabled by default) |

### Set by the `bash` tool

Every command the agent runs through the `bash` tool (foreground, background, PTY, ACP client terminal, and `name`-launched services) receives the current session identity:

| Variable          | Value                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------ |
| `PI_SESSION_ID`   | Current session ID                                                                         |
| `PI_SESSION_FILE` | Absolute path to the current session JSONL file; empty when not persisted (`--no-session`) |

Values are read when each tool call starts, so the next call follows `/fork`, `/new`, and `/resume`, and a call already under way keeps the session it started in. They are always set, so an empty value replaces a stale one inherited from a parent omp process. User `!` commands do not receive them.

```bash
echo "$PI_SESSION_ID"
```

### Remote file links

| Variable         | Behavior                                                                                                                                                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `PI_LINK_SCHEME` | Custom file-link scheme, for example `ompfile`, without `:` or `://`. Matched case-insensitively against `^[a-z][a-z0-9+.-]*$` and emitted lowercase. An invalid value logs a warning and keeps ordinary file/VS Code targets.             |
| `PI_LINK_HOST`   | Remote machine name used with `PI_LINK_SCHEME`, optionally with `:port`; defaults to `os.hostname()`. Letters, digits, `.`, `_`, and `-` only; an invalid value logs a warning and keeps ordinary targets. Has no effect without a scheme. |

The interactive TUI reads these variables once at startup. Both OSC 8 links and native TSP file links use the custom scheme, which takes precedence over VS Code targets. SDK hosts can call `applyFileLinkSetting` with an explicit configuration. Native image context-menu open actions keep local `file://` URLs because the action runs locally.

For example, start a remote session with `PI_LINK_SCHEME=ompfile PI_LINK_HOST=beelink omp`. A file link to `/work/a b.ts` at line 42, column 7 targets `ompfile://beelink/work/a%20b.ts?line=42&col=7`. The optional `line` and `col` query parameters preserve the supplied position; absent values are omitted. Plain `file:` links never carry these parameters.

The desktop protocol handler must route the host to the remote machine, percent-decode the pathname, and read the optional position parameters. Windows drive paths use `/C:/...`. UNC paths retain the file server in a double-slash pathname, for example `ompfile://beelink//nas/share/a.ts`. Malformed filesystem paths render without a link. File links the model writes in Markdown keep their own query or fragment (for example `#L10`), so handlers must ignore parameters they do not recognize. The handler itself is registered separately on the desktop.

## 11) OpenTelemetry export

OMP initializes OTLP export only when at least one signal has an endpoint. No export occurs without a configured endpoint. Configure an operator-provided or company in-house collector; its access controls, storage and retention are the operator's responsibility. Message-content capture defaults to `none`. Set `telemetry.otlpExportEnabled: false` (`/settings` → Providers → Privacy) to skip export even when endpoints are configured. `OTEL_SDK_DISABLED=true` also disables initialization.

| Variable group | Behavior |
| -------------- | -------- |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | Common endpoint fallback |
| `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`, `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT` | Per-signal endpoint; wins over the common endpoint |
| `OTEL_EXPORTER_OTLP_HEADERS` | Common OTLP request headers, as a `key=value,key2=value2` list with percent-encoded values |
| `OTEL_EXPORTER_OTLP_TRACES_HEADERS`, `OTEL_EXPORTER_OTLP_LOGS_HEADERS`, `OTEL_EXPORTER_OTLP_METRICS_HEADERS` | Per-signal request headers; merged per key over the common headers, which they override |
| `OTEL_TRACES_EXPORTER`, `OTEL_LOGS_EXPORTER`, `OTEL_METRICS_EXPORTER` | A list containing `none` disables that signal; an explicit non-empty list must include `otlp` to enable it |
| `OTEL_EXPORTER_OTLP_PROTOCOL` and per-signal `..._PROTOCOL` variants | Only `http/protobuf` is enabled by this runtime; another explicit protocol disables that signal |
| `OTEL_SERVICE_NAME`, `OTEL_RESOURCE_ATTRIBUTES` | OpenTelemetry resource metadata |
| `OTEL_LOG_LEVEL` | Minimum exported OMP log level |
| `OTEL_SDK_DISABLED` | `true` disables initialization |
| `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` | Message-content capture: `true`, `1`, `yes`, or `full` enables full capture; `summary` enables summary capture; unset or unrecognized values default to `none`. SDK hosts can explicitly set `AgentTelemetryConfig.captureMessageContent`. |

Header values are percent-decoded, so encode spaces and the `,`/`=` delimiters:

```bash
export OTEL_EXPORTER_OTLP_TRACES_ENDPOINT="http://localhost:4318/v1/traces"
export OTEL_EXPORTER_OTLP_TRACES_HEADERS="authorization=Bearer%20$OTEL_COLLECTOR_TOKEN"
```

## Security-sensitive variables

Treat these as secrets; do not log or commit them:

- Provider/API keys and OAuth/bearer credentials (all `*_API_KEY`, `*_TOKEN`, OAuth access/refresh tokens)
- Search and reader credentials (`EXA_API_KEY`, `BRAVE_API_KEY`, `PARALLEL_API_KEY`, `FIRECRAWL_API_KEY`)
- Private CA bundles referenced by `NODE_EXTRA_CA_CERTS`
- OTLP exporter headers (`OTEL_EXPORTER_OTLP_HEADERS` and the per-signal `..._{TRACES,LOGS,METRICS}_HEADERS` variants) — they carry ingest bearer tokens/project keys

Python runtime also explicitly strips many common key vars before spawning kernel subprocesses (`packages/coding-agent/src/eval/py/runtime.ts`).
